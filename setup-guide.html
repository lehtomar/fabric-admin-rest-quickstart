Power BI / Fabric Admin REST API – Setup & Test Guide

Step-by-step verification of the permissions required to call /admin/* endpoints.

🎯 Goal: confirm admin read and update calls succeed (no more 401 / 404)

🟡 TL;DR — easiest path

You don't need a service principal. Sign in as yourself with az login, make sure you have the Fabric administrator Entra role active, and call the API as a delegated user. Skip the SP / security group / tenant toggle dance entirely.

Use a service principal only when you need unattended automation (scheduled jobs, CI/CD, Azure Functions, etc.).

📋 Prerequisites

Accounts & roles

  • Microsoft Entra account in the target tenant with a Power BI / Fabric license.
  • Fabric administrator role assigned in the Entra admin center → Roles and administrators → Fabric administrator → Add assignment.
    Alternative the legacy "Power BI administrator" role also works.
    PIM if the role is PIM-eligible, it must be activated (not just eligible) and you must sign out / sign back in before the token sees it.
  • Not a guest / B2B user in the tenant.

Tools

  • Windows PowerShell 5.1 or PowerShell 7+ (pwsh).
  • Azure CLI – install, then verify with az --version.
  • The scripts from examples/.

What you do not need (for user mode)

  • App registration / client ID / client secret
  • Entra security group
  • Tenant settings toggles for service principals
  • Power BI API permissions in an app registration

1 Sign in to the target tenant

Replace <tenant-id> with your Microsoft Entra tenant ID.

az login --tenant <tenant-id>
az account show --query "{user:user.name, tenant:tenantId}" -o table

Expected: your UPN and the tenant ID you intended to sign into.

2 Run the diagnostic test

This probes four layers in order and tells you exactly where access breaks.

cd examples
.\Test-AdminApiAccess.ps1

Add -TestWorkspaceId <guid> at the end to also probe a write call:

.\Test-AdminApiAccess.ps1 -TestWorkspaceId <some-workspace-guid>

🛠️ If you still get 401 / 404

  1. Re-run az login --tenant <id> (token may have stale claims).
  2. In Entra admin center, confirm your account has Fabric administrator assigned. If via PIM → activate it.
  3. Wait ~15 minutes after a role change, then try again.
  4. Decode your token at jwt.ms – the wids claim should include the Fabric admin role GUID, and aud must be https://analysis.windows.net/powerbi/api.
  5. 404 from /admin/... is almost always "you weren't authorized" — don't treat it as "endpoint missing".

🤖 Service principal mode (unattended scenarios)

For unattended jobs you'll add this on top of the user flow:

  1. Create an Entra app registration. Do NOT grant it any Power BI API permissions.
  2. Create an Entra security group and add the service principal as a direct member.
  3. In Fabric Admin portal → Tenant settings → Admin API settings, enable both:
    • Service principals can access read-only admin APIs
    • Service principals can access admin APIs used for updates ← commonly missed
    Scope each to the group from step 2.
  4. Run the same diagnostic with -Mode SP -TenantId … -ClientId … -ClientSecret ….
